## 프로젝트 요약

### 문제

기존 기록 도구의 정해진 형식에서 벗어나 색감과 글의 배치까지 직접 결정할 수 있는 개인 공간이 필요했습니다.

### 해결

Markdown으로 글을 작성하면 코딩, 일상, 푸딩이, 포트폴리오 페이지에 자동으로 연결되는 Next.js 블로그를 만들었습니다.

### 결과

옵시디언에 직접 글을 쓰고 GitHub에 올리면 Cloudflare를 통해 인터넷에 배포되는 나만의 기록 시스템을 완성했습니다.

## 핵심 결과

### 4개의 콘텐츠 영역

코딩 기록, 일상, 푸딩이, 포트폴리오를 한 사이트에 모았습니다.

### Markdown 자동 페이지 생성

새 글 파일을 추가하면 목록과 상세 페이지가 같은 디자인으로 만들어집니다.

### GitHub·Cloudflare 배포

작성한 글을 저장하고 인터넷에 공개하는 흐름을 직접 운영합니다.

### 검색 기반 완성

Google Search Console과 사이트맵을 연결해 검색엔진이 글을 발견할 수 있게 했습니다.

## 만든 과정

### PLAN | 제작의 목적을 정했습니다

개인적인 공부 과정과 일상을 자유롭게 남기면서 포트폴리오로도 활용할 홈페이지를 만들자는 방향으로 목적을 정했습니다.

### DESIGN | 보이는 순서를 설계했습니다

AI가 제시한 시안 3개 중 가장 마음에 드는 시안으로 디벨롭했으며, 메인 섹션의 순서를 결정했습니다. 히어로 다음 글목록, 그리고 지루하지않게 푸딩이가 껴있고 마지막에 자격증과 포트폴리오를 올렸습니다.

### BUILD | 기록이 자동으로 연결되게 만들었습니다

Next.js와 TypeScript로 Markdown 글, 이미지, 태그가 화면에 나타나는 구조를 만들었습니다. 코딩을 직접 한건 아니지만 옵시디언에서 글을 쓰면 Github로 푸시하는 방식으로 쓸 수 있도록 배포를 자동화했습니다.

### PUBLISH | 직접 운영할 수 있게 연결했습니다

GitHub와 Cloudflare를 연결하고 Github가 업데이트되면 홈페이지로 1-2분 후 업데이트가 바로 이뤄지도록 했습니다. 또한 기록과 추후 SEO와 AEO를 고려하여 검색에 걸릴 수 있도록 사이트맵과 Search Console까지 설정했습니다.

# 어려웠던 점과 해결

- GitHub와 Cloudflare의 역할이 달라 자동 배포 흐름을 이해하는 데 시간이 필요했습니다.
- Obsidian의 이미지 이름과 홈페이지가 찾는 경로가 다르면 사진이 나타나지 않았습니다.
- commit과 push의 차이를 몰라 작성한 글이 홈페이지에 반영되지 않는 일도 있었습니다.

다 만든 뒤 실제 홈페이지의 작은 부분을 하나씩 확인했습니다. 이미지 경로, 공개 설정, 배포 기록을 순서대로 살펴보면서 원인을 찾았고, 반복되는 작업은 Markdown 파일만 추가하면 자동으로 처리되도록 바꿨습니다.
