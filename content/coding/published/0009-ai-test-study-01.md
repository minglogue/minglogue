# Session 1 — 생성형 AI·기초 모델 핵심

## 1) 생성형 AI·기초 모델 핵심
- **생성형 AI**: 학습한 패턴을 바탕으로 텍스트, 이미지, 코드, 음성 등 새로운 콘텐츠를 만든다.
- **기초 모델(Foundation Model, FM)**: 대규모 데이터로 사전 훈련되어 여러 작업에 재사용·맞춤화할 수 있는 범용 모델이다.
- 대표 사용 사례: 챗봇, 요약, 코드 생성, 이미지 생성, 개인화 콘텐츠, 검색 보조.
- 단순 데이터베이스 관리나 정해진 규칙만 수행하는 작업은 생성형 AI의 대표 사용 사례가 아니다.

> [!tip] 문제 풀이 기준
> 선택지에 **새 콘텐츠 생성**, **자연어 응답**, **요약**, **개인화**가 있으면 생성형 AI 가능성이 높다. 단순 저장·정렬·정확한 규칙 계산이면 전통적 소프트웨어가 더 적합할 수 있다.

## 2. 언제 AI/ML을 쓰는가

AI/ML 도입의 기대 편익보다 구축·운영·데이터 준비 비용이 크면 부적합하다.
반대로 다음 조건이면 적합성이 높다.

- 충분한 과거 데이터가 있다.
- 사람이 작성하기 어려운 패턴을 찾아야 한다.
- 예측, 분류, 추천, 자동화가 반복적으로 필요하다.
- 성과를 측정할 비즈니스 지표가 있다.

## 3. 멀티모달 모델

멀티모달 모델은 텍스트·이미지·오디오 등 여러 데이터 유형을 함께 처리한다. 예를 들어 마케팅 문구와 이미지를 함께 생성해 서로 일치하는 캠페인을 만들 수 있다.

| 개념         | 의미                  | 예시                 |
| ---------- | ------------------- | ------------------ |
| 단일 모달      | 한 종류의 데이터 처리        | 텍스트 전용 요약          |
| 멀티모달       | 여러 종류의 데이터를 통합 처리   | 이미지와 텍스트를 함께 이해·생성 |
| 크로스 도메인 성능 | 서로 다른 분야·데이터에서의 일반화 | 의료 텍스트와 이미지 모두 처리  |

## 4. 임베딩과 벡터 검색

- **임베딩**: 단어·문장·이미지의 의미를 연속적인 숫자 벡터로 표현한 것.
- 의미가 비슷한 항목은 벡터 공간에서 가까이 위치한다.
- 용도: 의미 기반 검색, 추천, 문서 유사도, RAG의 관련 문서 검색.
- 이 모의고사 기준 벡터 검색 서비스: **Amazon OpenSearch Service**, **Amazon Neptune**.

### 헷갈리는 개념

| 개념    | 핵심 질문                                |
| ----- | ------------------------------------ |
| 토큰화   | 텍스트를 모델이 처리할 작은 단위로 어떻게 나누는가?        |
| 청크화   | 긴 문서를 검색·처리 가능한 구간으로 어떻게 나누는가?       |
| 임베딩   | 의미를 숫자 벡터로 어떻게 표현하는가?                |
| 잠재 공간 | 모델이 학습한 추상적 특성이 배치되는 내부 표현 공간은 무엇인가? |

## 기출 포인트

- “연속 벡터 공간의 수학적 표현” → **임베딩**
- “텍스트와 이미지를 함께 처리” → **멀티모달**
- “추천 시스템에서 의미가 비슷한 상품 검색” → 임베딩 + 벡터 검색
- “생성 AI 도입의 주요 장점” → 낮은 진입 장벽, 빠른 개발, 비용 효율성, 확장성

## 30초 복습

- 생성형 AI는 새 콘텐츠를 생성한다.
- FM은 여러 작업에 맞춤화할 수 있는 범용 사전 훈련 모델이다.
- 임베딩은 의미를 벡터로 표현한다.
- 멀티모달은 여러 데이터 유형을 함께 처리한다.
- AI 비용이 편익보다 크면 도입하지 않는다.

# Session 2 — 프롬프트·추론·RAG

## 1. 좋은 프롬프트의 구성

좋은 프롬프트는 대체로 다음을 명확히 한다.

- **지침(Instruction)**: 무엇을 해야 하는가
- **맥락(Context)**: 어떤 배경과 자료를 참고해야 하는가
- **제약(Constraint)**: 길이, 형식, 금지 사항은 무엇인가
- **예시(Examples)**: 원하는 결과의 패턴은 무엇인가

구체적이고 간결하게 작성하고, 여러 표현을 실험하면서 품질을 비교한다.

### 프롬프트 기법 비교

| 기법 | 특징 | 적합한 상황 |
|---|---|---|
| Zero-shot | 예시 없이 지침만 제공 | 단순하거나 모델이 이미 잘 아는 작업 |
| One-shot | 예시 1개 제공 | 출력 형식을 빠르게 고정 |
| Few-shot | 예시 여러 개 제공 | 분류 기준·스타일·복잡한 패턴 학습 |
| 단계적 추론 유도 | 문제를 여러 단계로 나누도록 유도 | 다단계 분석·문제 해결 |
| Negative prompt | 원하지 않는 요소 명시 | 이미지·응답에서 특정 내용 제외 |

> [!warning] 안전과 품질은 별개 축
> 구체적인 프롬프트는 품질을 높이지만 유해 출력 방지를 완전히 보장하지 않는다. 안전을 위해 **가드레일**, 입력 검증, 접근 통제, 모니터링이 추가로 필요하다.

## 2. 추론 매개변수

### Temperature

- 낮음 → 무작위성 감소, 더 일관되고 사실 지향적인 출력
- 높음 → 다양성과 창의성 증가, 비결정성도 증가
- 재무 보고서처럼 일관성과 사실성이 중요하면 **낮은 temperature**가 적합하다.

### Top-k

다음 토큰 후보를 확률이 높은 상위 `k`개로 제한한다.

- `k` 감소 → 후보 감소 → 더 결정적·보수적
- `k` 증가 → 후보 증가 → 더 다양·창의적
- top-k는 출력 길이를 직접 보장하지 않는다.

### 입력·출력 길이

- 입력 한도는 모델이 한 번에 참고할 수 있는 정보량에 영향을 준다.
- 출력 한도는 생성 가능한 응답 길이를 제한한다.
- 너무 짧으면 필요한 세부 내용이 잘리고, 너무 길면 비용과 지연이 증가한다.

## 3. RAG

**Retrieval-Augmented Generation**은 질문과 관련된 외부 문서를 검색해 프롬프트에 넣고, 그 근거를 바탕으로 답을 생성하는 방식이다.

```text
사용자 질문 → 임베딩 생성 → 벡터 검색 → 관련 문서 주입 → 모델 답변
```

### RAG의 장점

- 모델 재훈련 없이 최신·사내 지식을 활용한다.
- 특정 조직의 문서를 근거로 답변 정확성을 높인다.
- 출처를 함께 제공하도록 설계할 수 있다.
- 환각을 줄이는 데 도움이 되지만 완전히 제거하지는 못한다.

### RAG와 미세 조정 비교

| 구분 | RAG | 미세 조정 |
|---|---|---|
| 목적 | 외부 지식 제공 | 행동·스타일·작업 성능 변경 |
| 지식 갱신 | 문서 저장소 갱신 | 재학습 필요 가능 |
| 데이터 | 검색 가능한 문서 | 고품질 훈련 예제 |
| 대표 문제 | “내부 규정에 근거해 답변” | “특정 형식으로 항상 분류” |

## 4. 환각과 비결정성

- **환각**: 실제 근거가 없거나 사실이 아닌 내용을 그럴듯하게 생성.
- **비결정성**: 같은 입력에도 실행마다 다른 결과가 나올 수 있음.
- 대응: RAG, 낮은 temperature, 가드레일, 근거 확인, 인간 검토, 평가·모니터링.

## 기출 포인트

- 복잡한 다단계 쿼리 → 단계적 추론 유도
- 사례로 출력 패턴 제시 → few-shot
- 사실적·일관된 재무 보고서 → 낮은 temperature
- top-k 감소 → 고확률 토큰 위주, 결정성 증가
- 재훈련 없이 내부 지식을 이용 → RAG/지식 검색

## 30초 복습

- 프롬프트는 지침·맥락·제약·예시를 명확히 한다.
- 낮은 temperature는 일관성, 높은 temperature는 창의성이다.
- top-k가 작을수록 후보가 줄어든다.
- RAG는 검색한 외부 지식을 생성 과정에 결합한다.
- 환각과 비결정성은 생성형 AI의 대표 한계다.
