# 개인 블로그 안에 포트폴리오 페이지 만들기

## 1. 무엇을 만들었나?

기존에는 홈페이지의 `Portfolio` 버튼을 누르면 별도의 포트폴리오 사이트로 이동했다.
이번에는 포트폴리오를 현재 블로그 안으로 가져왔다.
만들어진 주소는 다음과 같다.

- 포트폴리오 목록: `/portfolio`
- 프로젝트 상세 페이지: `/portfolio/my-record-window`

쉽게 표현하면 다음 구조다.

```
내 홈페이지
├── 코딩 기록
├── 일상 기록
├── 푸딩이 기록
└── 포트폴리오
    └── '내 기록창구 만들기' 프로젝트
```

블로그와 포트폴리오가 서로 다른 집에 있던 상태에서, 포트폴리오를 블로그라는 하나의 집 안으로 이사시킨 것이다.

---

## 2. 포트폴리오 글을 Markdown으로 작성했다

포트폴리오 프로젝트의 내용은 Markdown 파일에 저장했다.

```
content
└── portfolio
    └── 0001-my-record-window.md
```

Markdown 파일의 위쪽에는 프로젝트의 기본 정보가 들어간다.

```
---
title: "내 기록창구 만들기"
summary: "코딩 공부와 일상을 내가 원하는 방식으로 기록하는 개인 블로그"
period: "2026.07.27 ~ 진행 중"
contribution: "80%"
tools:
  - Next.js
  - React
  - TypeScript
  - Markdown
  - GitHub
  - Cloudflare
published: true
---
```

이 부분을 `프론트매터(frontmatter)`라고 한다.
프론트매터는 글의 내용이 아니라, 글을 설명하는 정보다.

책으로 비교하면 다음과 같다.

- `title`: 책 제목
- `summary`: 책 소개
- `period`: 작업 기간
- `contribution`: 내가 맡은 비율
- `tools`: 사용한 기술
- `published`: 홈페이지 공개 여부

`---` 아래에는 방문자가 실제로 읽는 프로젝트 설명을 작성한다.

```
# 프로젝트 소개

코딩 공부와 일상을 내가 원하는 모양과 형식으로
기록하기 위해 만든 개인 블로그입니다.

## 어려웠던 점

- GitHub와 Cloudflare 연결
- 이미지 경로 문제
- 자동 배포 구조 이해
```

즉, 하나의 Markdown 파일에는 두 가지 정보가 함께 들어 있다.

```
프로젝트 정보 + 프로젝트 본문
```

---

## 3. Markdown을 읽어주는 파일을 만들었다

Next.js는 Markdown 파일을 저절로 이해하지 못한다.

따라서 Markdown 파일을 찾아서 읽고, 홈페이지에서 사용할 수 있는 정보로 바꾸는 코드가 필요하다.

그 역할을 하는 파일이 `lib/portfolio.ts`다.

```
Markdown 파일
      ↓
lib/portfolio.ts
      ↓
Next.js가 사용할 수 있는 프로젝트 정보
```

이 파일은 다음과 같은 일을 한다.

1. `content/portfolio` 폴더에서 Markdown 파일을 찾는다.
2. 글 위쪽의 프론트매터를 읽는다.
3. 제목, 설명, 작업 기간, 기술 목록을 분리한다.
4. `published: true`인 프로젝트만 공개한다.
5. 파일 이름을 이용해 페이지 주소를 만든다.

예를 들어 파일 이름이 다음과 같다면,

```
0001-my-record-window.md
```

앞의 번호와 확장자를 제외하고 다음 주소를 만든다.

```
/portfolio/my-record-window
```

파일 이름이 홈페이지 주소로 변하는 것이다.

---

## 4. 포트폴리오 목록 페이지를 만들었다

목록 페이지는 다음 파일이 담당한다.

```
app/portfolio/page.tsx
```

이 파일은 `lib/portfolio.ts`에 프로젝트 목록을 요청한다.

```
app/portfolio/page.tsx
        ↓ 프로젝트 목록 요청
lib/portfolio.ts
        ↓ Markdown 읽기
content/portfolio
```

가져온 정보는 프로젝트 카드로 표시한다.

카드에는 다음 정보가 들어간다.

- 대표 이미지
- 프로젝트 번호
- 프로젝트 이름
- 짧은 소개
- 사용한 기술
- 프로젝트 상세 페이지 링크

쉽게 말하면 목록 페이지는 서점의 책 진열대와 같다.

책의 표지와 제목을 보여주고, 하나를 선택하면 자세한 내용을 볼 수 있게 해준다.

---

## 5. 프로젝트 상세 페이지를 만들었다

프로젝트 하나의 자세한 내용을 보여주는 파일도 만들었다.

```
app/portfolio/[slug]/page.tsx
```

여기서 `[slug]`는 프로젝트마다 달라지는 주소 부분이다.

예를 들어 다음 주소가 있다.

```
/portfolio/my-record-window
```

이 주소에서는 다음 부분이 `slug`다.

```
my-record-window
```

새로운 프로젝트 파일을 추가하면 slug도 달라진다.

```
0002-pudding-project.md
        ↓
/portfolio/pudding-project
```

따라서 프로젝트마다 TSX 페이지를 새로 만들 필요가 없다.
`[slug]/page.tsx`라는 하나의 틀이 여러 프로젝트의 내용을 바꿔 끼워서 보여준다.

붕어빵으로 표현하면 다음과 같다.

```
[slug]/page.tsx = 붕어빵 틀
Markdown 내용 = 붕어빵 속 재료
완성된 상세 페이지 = 붕어빵
```

프로젝트가 10개가 되어도 상세 페이지 틀은 하나만 있으면 된다.

---

## 6. 대표 이미지를 연결했다

프로젝트에서 사용할 대표 이미지는 `content/media` 폴더에 보관한다.

```
content
├── media
│   └── 스크린샷.png
└── portfolio
    └── 0001-my-record-window.md
```

Markdown의 프론트매터에서 이미지 파일 이름을 지정한다.

```
cover: "스크린샷.png"
```

`lib/portfolio.ts`는 이 이름을 보고 실제 이미지 파일을 찾아준다.

```
Markdown에 적힌 이미지 이름
            ↓
lib/portfolio.ts가 이미지 검색
            ↓
포트폴리오 화면에 이미지 표시
```

이미지 파일 이름이 다르거나 이미지가 `content/media`에 없다면 화면에 표시되지 않을 수 있다.

---

## 7. 홈페이지 메뉴를 연결했다

기존의 `Portfolio` 버튼은 외부 포트폴리오 주소로 연결되어 있었다.

이를 현재 홈페이지 안의 주소로 변경했다.

```
기존
Portfolio → 외부 포트폴리오 사이트

변경
Portfolio → /portfolio
```

이제 방문자는 다른 사이트로 나가지 않고 블로그 안에서 포트폴리오를 볼 수 있다.
상단 메뉴와 홈페이지 아래쪽 포트폴리오 버튼 모두 같은 `/portfolio` 주소로 연결했다.

---

## 8. 디자인을 추가했다

페이지 구조만 만들면 글과 이미지가 아무런 꾸밈 없이 표시된다.
따라서 `app/globals.css`에 포트폴리오용 디자인 규칙을 추가했다.

CSS는 화면을 꾸미는 역할을 한다.

```
TSX = 화면에 무엇을 놓을지 결정
CSS = 그것을 어떤 모양으로 보여줄지 결정
```

이번에 CSS로 정한 것은 다음과 같다.

- 제목의 크기와 굵기
- 노란색 강조 표시
- 프로젝트 카드의 간격
- 대표 이미지 크기
- 기술 이름의 태그 모양
- 작업 기간과 참여도 정보 칸
- 모바일 화면에서의 배치

TSX가 레고 블록을 놓는 일이라면, CSS는 블록의 색깔과 크기, 간격을 정하는 일이다.

---

## 9. 새 프로젝트용 템플릿을 만들었다

앞으로 포트폴리오 글을 쉽게 추가할 수 있도록 템플릿을 만들었다.

```
content/templete/portfolio-template.md
```

새 프로젝트를 추가할 때는 이 파일을 복사한 뒤 내용만 변경하면 된다.

예를 들면 다음과 같다.

```
portfolio-template.md 복사
        ↓
0002-new-project.md로 이름 변경
        ↓
제목, 기간, 기술, 본문 작성
        ↓
GitHub에 push
        ↓
포트폴리오 목록에 자동 표시
```

매번 포트폴리오 페이지의 코드를 새로 작성할 필요가 없다.

## 10. 사이트맵에 포트폴리오 주소를 넣었다

사이트맵은 검색엔진에게 홈페이지의 페이지 주소를 알려주는 지도다.

기존 사이트맵에 다음 주소들을 추가했다.

```
/portfolio
/portfolio/my-record-window
```

앞으로 공개된 포트폴리오 Markdown 파일을 추가하면 해당 상세 페이지 주소도 사이트맵에 포함된다.

```
새 프로젝트 작성
      ↓
상세 페이지 생성
      ↓
사이트맵에 주소 포함
      ↓
검색엔진이 페이지를 발견
```

사이트맵에 포함됐다고 바로 Google 검색 결과에 나타나는 것은 아니다.
Google이 사이트맵을 읽고 페이지를 방문한 뒤, 검색 결과에 넣을 가치가 있는지 판단하는 시간이 필요하다.

## 11. 홈페이지가 제대로 만들어지는지 검사했다

코드를 수정한 다음에는 빌드를 실행했다.
빌드는 작성한 코드를 실제 홈페이지로 만들 수 있는지 검사하는 과정이다.

```
내가 작성한 코드
      ↓
빌드 검사
      ↓
실제 배포 가능한 홈페이지
```

오타, 잘못된 주소, 이해할 수 없는 TypeScript 코드 등이 있으면 빌드 과정에서 오류가 발생한다.
이번 빌드에서는 다음 페이지가 정상적으로 만들어지는 것을 확인했다.

```
/portfolio
/portfolio/my-record-window
```

---

## 12. GitHub에 저장했다

검사가 끝난 코드는 GitHub에 저장했다.
전체 흐름은 다음과 같다.

```
파일 수정
  ↓
commit
  ↓
push
  ↓
GitHub에 새 코드 저장
```

여기서 각각의 뜻은 다음과 같다.

- `commit`: 변경 내용을 하나의 저장 지점으로 묶기
- `push`: 저장 지점을 내 컴퓨터에서 GitHub로 보내기

commit만 하고 push하지 않으면 GitHub에는 변경 내용이 올라가지 않는다.

---

## 13. Cloudflare에 배포했다

마지막으로 GitHub에 저장된 홈페이지를 Cloudflare Workers에 배포했다.

```
Markdown과 코드 작성
        ↓
GitHub에 push
        ↓
Cloudflare가 홈페이지 제작
        ↓
인터넷 주소에 새 화면 공개
```

배포 후 실제 인터넷 주소로 들어가서 다음 내용을 확인했다.

- Portfolio 메뉴가 보이는가?
- 포트폴리오 목록이 열리는가?
- 프로젝트 상세 페이지가 열리는가?
- 대표 이미지가 보이는가?
- 작업 기간과 참여도가 표시되는가?
- Markdown의 제목과 목록이 올바르게 보이는가?
- GitHub 및 사이트 방문 버튼이 연결되는가?

코드가 정상적으로 빌드되는 것과 실제 화면이 정상적으로 보이는 것은 서로 다른 문제이기 때문에 둘 다 확인해야 한다.

# 앞으로 새 포트폴리오를 추가하는 방법

## 1단계: 템플릿 복사

```
content/templete/portfolio-template.md
```

## 2단계: 파일 이름 변경

```
0002-project-name.md
```

파일 이름은 영문과 대시를 사용하는 것이 안전하다.

## 3단계: 프로젝트 정보 작성

```
---
title: "프로젝트 이름"
summary: "프로젝트 한 줄 소개"
period: "2026.08 ~ 진행 중"
contribution: "100%"
published: true
---
```

## 4단계: 본문 작성

```
# 프로젝트 소개

어떤 프로젝트인지 설명한다.

## 만든 이유

왜 만들었는지 설명한다.

## 어려웠던 점

- 어려움 1
- 어려움 2

## 프로젝트 결과

무엇을 완성했는지 설명한다.
```

## 5단계: 대표 이미지 넣기

이미지를 `content/media` 폴더에 넣고 프런트매터의 `cover`에 같은 파일 이름을 적는다.

## 6단계: GitHub에 올리기

```
commit → push → Cloudflare 배포
```

배포가 끝나면 포트폴리오 목록과 상세 페이지에서 확인한다.

# 이번 작업의 핵심

포트폴리오 페이지를 하나씩 직접 코딩하는 구조가 아니다.

프로젝트 내용을 Markdown 파일로 작성하면, Next.js가 같은 디자인 틀에 내용을 자동으로 넣어 페이지를 만드는 구조다.

```
Markdown 작성 = 프로젝트 등록
```

따라서 앞으로는 코드를 크게 수정하지 않고도 포트폴리오를 계속 추가할 수 있다.
